# GitHub Actions Automation Setup Guide

This guide explains how to set up automated email scheduling and email checking using GitHub Actions.

## Overview

Two GitHub Actions workflows automate the review analysis system:

1. **Weekly Email Scheduler** - Automatically sends weekly reports every Monday at 9:00 AM IST
2. **Email Checker** - Checks the inbox every 10 minutes for analysis requests and processes them

## Prerequisites

- GitHub repository (public or private with GitHub Actions enabled)
- All required API keys and credentials (see below)
- Data files committed to repository (or generated by workflows)

## Required GitHub Secrets

You need to configure the following secrets in your GitHub repository:

### 1. Navigate to Repository Settings

1. Go to your GitHub repository
2. Click on **Settings** (top menu)
3. In the left sidebar, click on **Secrets and variables** → **Actions**
4. Click **New repository secret**

### 2. Add Required Secrets

Add the following secrets:

| Secret Name | Description | Example |
|------------|-------------|---------|
| `SENDGRID_API_KEY` | SendGrid API key for sending emails | `SG.xxxxxxxxxxxxx` |
| `GROQ_API_KEY` | Groq API key for LLM operations | `gsk_xxxxxxxxxxxxx` |
| `EMAIL_PASSWORD` | Gmail App Password for IMAP access | `xxxx xxxx xxxx xxxx` |

### 3. How to Get Each Secret

#### SENDGRID_API_KEY
1. Log in to [SendGrid](https://app.sendgrid.com/)
2. Go to **Settings** → **API Keys**
3. Click **Create API Key**
4. Give it a name (e.g., "GitHub Actions")
5. Select **Full Access** or **Restricted Access** (with Mail Send permissions)
6. Copy the API key (you'll only see it once!)

#### GROQ_API_KEY
1. Go to [Groq Console](https://console.groq.com/)
2. Sign in or create an account
3. Navigate to **API Keys** section
4. Click **Create API Key**
5. Copy the API key

#### EMAIL_PASSWORD
1. Go to your Google Account settings
2. Navigate to **Security** → **2-Step Verification**
3. Scroll down to **App passwords**
4. Select **Mail** and **Other (Custom name)**
5. Enter "GitHub Actions" as the name
6. Copy the generated 16-character password

> **Note:** For detailed IMAP setup instructions, see [IMAP_POLLING_SETUP.md](./IMAP_POLLING_SETUP.md)

## Workflow Configuration

### Weekly Email Scheduler

**File:** `.github/workflows/weekly-scheduler.yml`

**Schedule:** Every Monday at 9:00 AM IST (3:30 AM UTC)

**What it does:**
- Finds the latest week's report data
- Generates and sends the weekly email report
- Uses the `send-latest` CLI command

**Customizing the schedule:**

Edit the cron expression in `.github/workflows/weekly-scheduler.yml`:

```yaml
schedule:
  - cron: '30 3 * * 1'  # Monday 9:00 AM IST
```

Cron format: `minute hour day month day-of-week`
- IST is UTC+5:30, so 9:00 AM IST = 3:30 AM UTC
- `1` = Monday (0 = Sunday, 1 = Monday, ..., 6 = Saturday)

**Examples:**
- Every Monday at 9:00 AM IST: `'30 3 * * 1'`
- Every Friday at 5:00 PM IST: `'30 11 * * 5'` (5:00 PM IST = 11:30 AM UTC)
- Every day at 8:00 AM IST: `'30 2 * * *'` (8:00 AM IST = 2:30 AM UTC)

### Email Checker

**File:** `.github/workflows/email-checker.yml`

**Schedule:** Every 10 minutes

**What it does:**
- Connects to IMAP server (Gmail)
- Checks for emails with subject `[ANALYZE]`
- Processes analysis requests
- Sends reply emails with analysis results

**Customizing the polling interval:**

Edit the cron expression in `.github/workflows/email-checker.yml`:

```yaml
schedule:
  - cron: '*/10 * * * *'  # Every 10 minutes
```

**Examples:**
- Every 5 minutes: `'*/5 * * * *'`
- Every 15 minutes: `'*/15 * * * *'`
- Every hour: `'0 * * * *'`

> **Note:** GitHub Actions free tier allows 2000 minutes/month. Running every 10 minutes = ~4,320 minutes/month, which exceeds the free tier. Consider:
> - Using a longer interval (e.g., every 30 minutes or hourly)
> - Upgrading to GitHub Pro
> - Using a different automation service for frequent polling

## Manual Workflow Execution

Both workflows can be triggered manually:

1. Go to your GitHub repository
2. Click on **Actions** tab
3. Select the workflow (e.g., "Weekly Email Scheduler")
4. Click **Run workflow** button
5. Select the branch and click **Run workflow**

## Data Files Requirement

The workflows assume that data files exist in the repository:

- `data/raw/reviews_*.json` - Raw review data
- `data/classified/insights_*_report.json` or `clusters_*_report.json` - Classification reports

**Options:**

1. **Commit data files to repository** (for small datasets)
   ```bash
   git add data/
   git commit -m "Add data files"
   git push
   ```

2. **Generate data in workflow** (modify workflows to run scraping first)
   - Add a step to run `python -m src.main --start-date ... --end-date ...`
   - This will increase workflow execution time

3. **Use GitHub Actions artifacts/cache** (advanced)
   - Store data files as artifacts from a separate workflow
   - Download artifacts in the email workflows

## Troubleshooting

### Workflow Fails: "Secret not set"

**Problem:** Workflow fails with "Error: [SECRET_NAME] secret is not set"

**Solution:**
1. Go to repository **Settings** → **Secrets and variables** → **Actions**
2. Verify all required secrets are added
3. Check secret names match exactly (case-sensitive)

### Workflow Fails: "No data files found"

**Problem:** Workflow fails with "Could not find latest week data"

**Solution:**
1. Ensure data files are committed to the repository
2. Check file paths match expected locations:
   - `data/raw/reviews_*.json`
   - `data/classified/insights_*_report.json` or `clusters_*_report.json`
3. Verify files are in the correct branch (usually `main` or `master`)

### Email Not Sending

**Problem:** Workflow succeeds but no email is received

**Solution:**
1. Check SendGrid dashboard for email delivery status
2. Verify `SENDGRID_API_KEY` secret is correct
3. Check recipient email addresses in `config/email.json`
4. Review workflow logs for error messages

### IMAP Connection Fails

**Problem:** Email checker fails to connect to IMAP

**Solution:**
1. Verify `EMAIL_PASSWORD` is a Gmail App Password (not regular password)
2. Check IMAP settings in `config/inbound_email.json`
3. Ensure 2-Step Verification is enabled on Gmail account
4. Review workflow logs for specific error messages

### Workflow Timeout

**Problem:** Workflow exceeds timeout limit

**Solution:**
1. Weekly scheduler timeout: 30 minutes (should be sufficient)
2. Email checker timeout: 5 minutes (should be sufficient)
3. If timeout occurs, check logs for slow operations
4. Consider optimizing data processing or reducing data size

## GitHub Actions Limits

### Free Tier Limits

- **2,000 minutes/month** of workflow execution
- **500 MB storage**
- **1 GB bandwidth/month**

### Calculating Usage

- Weekly scheduler: ~5 minutes/week = ~20 minutes/month
- Email checker: ~1 minute/run × 6 runs/hour × 24 hours × 30 days = ~4,320 minutes/month

**Recommendation:** For email checker, use a longer interval (30 minutes or hourly) to stay within free tier limits.

### Upgrading

If you need more minutes:
- **GitHub Pro:** $4/month - 3,000 minutes/month
- **GitHub Team:** $4/user/month - 3,000 minutes/month
- **GitHub Enterprise:** Custom pricing

## Security Best Practices

1. **Never commit secrets** - Always use GitHub Secrets
2. **Use least privilege** - Give API keys only necessary permissions
3. **Rotate secrets regularly** - Update secrets every 90 days
4. **Monitor workflow runs** - Review logs for suspicious activity
5. **Limit workflow access** - Use branch protection rules

## Alternative Solutions

If GitHub Actions doesn't meet your needs, consider:

1. **Cloud Functions** (AWS Lambda, Google Cloud Functions, Azure Functions)
   - Pay-per-use pricing
   - Better for frequent polling
   - More complex setup

2. **VPS/Cloud Server** (DigitalOcean, AWS EC2, etc.)
   - Full control
   - Can run continuously
   - Requires server management

3. **Cron Jobs on Local Machine**
   - Free
   - Requires always-on machine
   - Not suitable for production
